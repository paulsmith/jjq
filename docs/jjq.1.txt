DDEESSCCRRIIPPTTIIOONN
       jjjjqq is a local merge queue for jjjj(1) (Jujutsu VCS).  It queues
       revisions for merging to a trunk bookmark, processes them in FIFO
       order, and gates each merge on a configurable check command.  This
       prevents the "works on my branch" problem where changes pass checks
       individually but fail when combined with concurrent work.

       jjjjqq stores all state inside the jj repository using bookmarks and an
       isolated metadata branch.  No external database or service is required.

CCOOMMMMAANNDDSS
   iinniitt [----ttrruunnkk _b_o_o_k_m_a_r_k] [----cchheecckk _c_o_m_m_a_n_d] [----ssttrraatteeggyy _s_t_r_a_t_e_g_y]
       Initialize jjq in the current repository.  Sets up the metadata branch
       and configures the trunk bookmark and check command.

       With ----ttrruunnkk and ----cchheecckk flags, runs non-interactively.  Without flags,
       prompts for each value.  The trunk bookmark defaults to mmaaiinn if that
       bookmark exists, or mmaasstteerr as a fallback.

       If stdin is not a terminal and required flags are missing, exits with
       an error.

       Refuses to run if jjq is already initialized.  Use jjjjqq ccoonnffiigg to change
       settings after initialization.

       After configuration, runs jjjjqq ddooccttoorr to validate the setup.

   ppuusshh _r_e_v_s_e_t
       Queue a revision for merging to trunk.  The revset must resolve to
       exactly one revision.

       Before queuing, jjjjqq creates a temporary merge commit between the trunk
       and the candidate to check for textual conflicts.  If conflicts are
       detected, the push is rejected with exit code 1.

       Push is idempotent for the same change ID: if the change is already
       queued or failed, the stale entry is cleared and the revision is
       re-queued.  If the exact same commit ID is already queued, the push is
       rejected as a duplicate (usage error).

       If the queued commit is the invoking workspace's working-copy commit,
       the working copy is moved to a new empty child (as jjjj ccoommmmiitt does) and
       a note is printed.  Later edits in the workspace then go to a new
       change instead of amending the queued commit -- jj bookmarks follow
       rewritten commits, so once the item lands, further amendments would
       silently move trunk.

              jjq push @              # queue the working copy
              jjq push feat-xyz@      # queue a workspace's working copy
              jjq push abc123         # queue by change ID

   rruunn [----aallll] [----ssttoopp--oonn--ffaaiilluurree] [----jjoobbss _N]
       Process the next queued item.  Claims the item by renaming its bookmark
       from jjjjqq//qquueeuuee//_N_N_N_N_N_N to jjjjqq//rruunnnniinngg//_N_N_N_N_N_N,, creates a temporary jj
       workspace to test the candidate against trunk, then runs the configured
       check command inside it.  Success produces an in-memory validation
       receipt bound to the sequence ID, candidate change and commit IDs,
       trunk commit, checked workspace commit, strategy, and exact check
       command.  Immediately before moving trunk, jjq verifies all of those
       facts still match.  If the receipt is stale (for example, trunk or
       configuration changed), its unchanged claim returns to the same queue
       position for a fresh check.  An out-of-band removed or retargeted claim
       is discarded rather than landed.  While claimed, the item shows under
       "Running" in jjjjqq ssttaattuuss and cannot be deleted or requeued.  A claim
       left behind by a crashed runner is recovered back to its queue position
       on the next run.

       On success, the trunk bookmark advances and the temporary workspace is
       cleaned up.  If the landed change is still some workspace's
       working-copy commit (pushed from a different workspace, so ppuusshh could
       not move that working copy), a warning names the workspace: run jjjj nneeww
       there before editing, or the workspace's next snapshot amends the
       landed commit and trunk follows it.

       On failure (conflicts or check command failure), the item moves to the
       failed list.  The temporary workspace is preserved for debugging.

       If the trunk bookmark or check configuration moves during processing
       (e.g., another runner advanced trunk), the receipt is rejected and the
       item is requeued for a fresh check.

       With ----aallll, processes items in a loop until the queue is empty.
       Failures are recorded and processing continues unless ----ssttoopp--oonn--ffaaiilluurree
       is set. Reports the count of successes and failures.

       ----jjoobbss sets a maximum number of concurrent speculative checks. It
       defaults to 1 and is valid only with ----aallll.  For merge strategy, jjq
       checks a bounded FIFO chain of predicted trunk states, but lands only
       in FIFO order after an exact receipt base matches trunk. A failed or
       tree-mutating predecessor invalidates later predictions and they are
       rechecked from the real trunk. Rebase and ----ssttoopp--oonn--ffaaiilluurree currently
       run serially: rebase's disposable duplicate cannot safely supply an
       exact commit-bound predicted base for the original candidate.

       Returns 0 if all processed items succeeded (or the queue was empty).
       Returns 2 if any items failed. Returns 1 if another queue runner is
       active, the check command is not configured, a conflict is detected, or
       trunk moved during processing.

       After processing at least one item, and again in jjjjqq cclleeaann, jjq
       abandons residue leaves: visible bookmark-less commits, no workspace's
       working copy, whose exact commit ID was recorded as the queued
       candidate of a submission that landed (the obsolete originals a failed
       first attempt leaves behind once a fix lands, reached through the
       requeue lineage).  Matching is on commit ID, never change ID, so a
       divergent copy of a landed change that carries unlanded edits is kept.
       Abandoned and kept leaves are logged; cleanup failures are warnings and
       never fail the run.

   ccaanncceell _i_d
       Cancel a queued or running submission. Queued work is removed
       immediately.  For a running item, jjq durably records intent and the
       owning runner terminates the check's process group with TERM,
       escalating to KILL after one second.  Cancellation is idempotent and is
       not a failure: it does not produce PPAARRTTIIAALL or trigger
       ----ssttoopp--oonn--ffaaiilluurree.

       Cancellation is not rollback. The runner serializes accepted intent
       with all terminal outcomes. If the final trunk compare-and-swap already
       won, landing wins and a later cancel reports that the item is no longer
       cancellable.  Accepted intent survives a runner crash and recovery
       completes the canceled history event and cleanup without requeuing or
       rerunning the item.

   cchheecckk [----rreevv _r_e_v_s_e_t] [--vv]
       Run the configured check command against a revision in a temporary
       workspace without any queue processing.  Useful for verifying that the
       check command works before queuing items.

       Defaults to the current working copy (@@) if ----rreevv is not specified.

       With --vv (----vveerrbboossee), prints the workspace path, shell, and all
       environment variables before running the check command.  Useful for
       diagnosing path or environment issues.

       The temporary workspace is always cleaned up, regardless of outcome.
       Exits 0 if the check passes; 1 if it fails.

   hhiissttoorryy [[iidd]] [[----jjssoonn]] || ----cchhaannggee cchhaannggee__iidd [[----jjssoonn]]

   rreeqquueeuuee _i_d
       Re-push a failed item back onto the queue under a new sequence ID.
       Runs the same pre-flight conflict check and working-copy handling as
       ppuusshh and clears the failed entry and its workspace on success.  A
       shortcut for retrying an item without changes; use jjjjqq ppuusshh after
       fixing the revision instead.

   ddeelleettee _i_d
       Remove an item from the queue or the failed list by its sequence ID.
       The sequence ID is the number shown in ssttaattuuss output and ppuusshh
       confirmation messages.  An item claimed by an active queue runner
       cannot be deleted until the run finishes; a stale claim left by a
       crashed runner is removed along with its leftover workspace.

   rreejjeecctt _i_d ----rreeaassoonn _t_e_x_t
       Mark an item failed without running it and record _t_e_x_t as the reason.
       A queued item moves to the failed list; an already-failed item gains or
       replaces the reason. An item claimed by a runner is refused (suggest
       jjjjqq ccaanncceell).  The reason appears in ssttaattuuss and ssttaattuuss ----jjssoonn as
       rreejjeecctt__rreeaassoonn, and is recorded durably as a rreejjeecctteedd history event.

       A failed item with a reason is terminal: policy rejections and
       escalated failures carry one, while bare check failures do not.  The
       reason is stored as a single line; newlines collapse to spaces.

   wwaaiitt _r_e_v_s_e_t [----iinntteerrvvaall _s_e_c_s] [----ttiimmeeoouutt _s_e_c_s]

       resolves to one change (a short change ID from ppuusshh output is typical).
       Polls every _s_e_c_s seconds (default 10).  Verdicts are checked in this
       order each poll:

              llaannddeedd The candidate's change ID is an ancestor of trunk: exit
                     0. Landed takes precedence over any stale entry.

              rreejjeecctteedd
                     A failed entry with a recorded reason exists: the reason
                     and item ID are printed to stdout and the exit code is 1.

              ppeennddiinngg

              uunnkknnoowwnn

       uuppddaattee--ssttaallee and start from trunk rather than resuming the old commit.

   ddooccttoorr [----ffiixx]
       Validate that the jjq environment is correctly configured.  Checks the
       trunk bookmark, check command, sequence counter, conflicted jjq
       bookmarks, lock state, stale claims, and workspace preconditions.  Each
       check is reported as ookk, WWAARRNN, or FFAAIILL.  When a check fails, a
       suggested fix is shown.

       With ----ffiixx, repairs a conflicted jjq metadata bookmark before running
       the checks: the conflict side with the highest sequence counter is
       kept, so no sequence IDs are ever reused.  Conflicted queue or failed
       bookmarks point at user commits and are never repaired automatically.

       Exits 0 if no failures are found (warnings are tolerated).  Exits 1 if
       any check fails.

       cchheecckk__ccoommmmaanndd (required)

CCOONNFFIIGGUURRAATTIIOONN
       jjjjqq stores configuration on an isolated metadata branch (jjjjqq//__//__)
       parented to the repository root.  This branch never appears in normal
       jjjj lloogg output and does not pollute user history.

       Always configure cchheecckk__ccoommmmaanndd before using jjjjqq rruunn.  If cchheecckk__ccoommmmaanndd
       is unset, jjjjqq rruunn will refuse to process items.

LLOOCCKKIINNGG
       jjjjqq uses flock-based file locks in _._j_j_/_j_j_q_/_l_o_c_k_s_/ under the shared
       repository directory, so invocations from any jj workspace contend on
       the same locks.  Locks are released automatically by the OS when the
       holding process exits, so stale locks cannot occur.

       rruunn    Ensures only one jjjjqq rruunn processes the queue at a time.  A
              second runner exits immediately with code 1 ("another queue
              runner is active").

       mmeettaa   Serializes all writes to the metadata branch: sequence ID
              allocation, configuration, and workspace records.  Writers wait
              for a concurrent writer to finish (concurrent pushes serialize)
              and exit with code 3 only after the timeout.  Reads take no
              lock; each command pins one metadata commit and reads every
              value from it.

       cchheecckk  Held shared by each jjjjqq cchheecckk for its workspace's lifetime;
              concurrent checks coexist, while jjjjqq cclleeaann probes the lock
              exclusively and refuses while any check is active.

DDAATTAA MMOODDEELL
       Queue items are jj bookmarks named jjjjqq//qquueeuuee//_N_N_N_N_N_N where _N_N_N_N_N_N is a
       zero-padded sequence ID.  The item claimed by an active queue runner is
       renamed to jjjjqq//rruunnnniinngg//_N_N_N_N_N_N for the duration of its run.  Failed
       items use jjjjqq//ffaaiilleedd//_N_N_N_N_N_N..  The metadata branch at jjjjqq//__//__ stores the
       last allocated ID, configuration, and an operation log (commit messages
       include trailers such as sequence IDs and workspace paths).

       With the merge strategy, successful merges are ordinary jj commits with
       two parents (trunk and candidate).  With the rebase strategy, the
       candidate is duplicated onto trunk to produce linear history,
       preserving the original change ID.  Failed merges are preserved as
       conflicted commits with descriptions like "Failed: merge N (conflicts)"
       or "Failed: merge N (check)". The workspace path is recorded in
       trailers for later cleanup.

       Initialize a project:

              jjq init --trunk main --check "make test && make lint"

       Developer queues work:

              jjq push @

       Process the queue:

              jjq run          # one item
              jjq run --all    # drain the queue

       Handle a failure:

              jjq status                    # see what failed
              jj rebase -b <rev> -d main    # rebase onto current trunk
              ... resolve conflicts ...
              jjq push <rev>                # re-queue
              jjq run                       # retry

       Clean up:

              jjq clean

       The check command runs in a temporary workspace that has the merged
       state of trunk + candidate.  Any command that works in a normal
       checkout works here.

       Push is cheap.  If you're unsure whether your revision will conflict,
       just push it -- jjjjqq checks for conflicts up front and rejects the push
       immediately.

       For parallel development with multiple agents or developers, use jj
